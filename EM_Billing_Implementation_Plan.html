EM Billing System — Implementation Plan

Cart-based EM requests with PI approval · auto-enable or RSSD Jira · monthly per-PTA finance invoicing · carry-forward debt tracking and backcharge ledger. Merges the finalized plan with the workflow diagrams.

1) Key Design Decisions Finalized July 10, 2026

Request flow

  • Catalog & cart page in each project's EM menu (som-prod v1, Design right required); catalog, fees, and a new per-EM auto_enable flag live as records in the EM-records project (PID 16000).
  • Checkout validates the PTA (regex) and pre-creates a record in a dedicated request-tracking REDCap project, then redirects to its survey (no data in the URL).
  • Requester picks the PI/Admin approver on the survey via the Stanford person-lookup EM; a REDCap Alert emails the PI the approval survey.
  • PI approves/rejects the whole request (PTA + all EMs, one decision).
  • On approval (redcap_save_record hook): PTA syncs into pta_accounts + project_pta_mapping; flagged EMs auto-enable (failure → approval_error, retryable); the rest get one RSSD Jira ticket per request (REST API), awaiting_super_user until reconciliation sees the manual enable.
  • The planned em_enable_requests/em_enable_request_items entities are not built — tracking-project records supersede them.

Billing, invoice & debt

  • Line-level storage; grouping is a view. finance_billing_lines (one per project+EM+month, PTA snapshotted) under finance_billing_runs; run view groups PTA → project → EM. Replaces the JSON-snapshot monthly_pta_reports.
  • Debt owner = PTA. Outstanding Balances ledger keyed by PTA — open rejected/hold lines attributed to each project's current PTA (snapshot kept for audit).
  • Finance rejects per PTA. Editable CSV = one row per PTA; import fans status out to that PTA's pending lines. Read-only per-line detail CSV alongside.
  • Carry-forward re-bills the project's current PTA — same amount, attempt+1, carried_from_line_id; created regardless of current enablement (already-incurred debt).
  • Unmapped projects → lines at hold + "No PTA mapping" (never dropped; carry forward until mapped).
  • Manual overrides any time (incl. post-finalize) with required audited note — closes settled backcharges.
  • Scope v1: som-prod only (instance = som-prod); multi-instance keys deferred.

Deactivation & reconciliation

  • Module-injected UI on REDCap's core EM manager page: per-EM fee/PTA/status annotations + a module-owned Disable button (required reason, immediate, audited). Re-enable = full new request.
  • Nightly reconciliation cron: out-of-band disables → auto_detected acknowledgment queue; Jira-resolved manual enables → line flipped to enabled.
  • Go-live baseline: one-time seeding of grandfathered tracking records for every currently-enabled billable EM.

Security fix (must ship first)

ajax/finance_report_action.php and ajax/finance_report_download.php are currently in no-auth-pages with no permission or token check — remove them from no-auth-pages and guard super-user-only (page + both endpoints).

6) Data Model

New entities (REDCapEntity)

  • finance_billing_runs — run_month, run_year, status (draft/exported/finalized), generated_by, exported_at, imported_at, total_amount, total_lines, carried_amount.
  • finance_billing_lines — run_id, instance, project_id, project_title, module_prefix, amount, pta_id/pta_number (snapshot; empty = unmapped), status, finance_note, status_source (generation/csv_import/manual), status_updated_by/at, carried_from_line_id, attempt_number, charge_entity_id.

Removed / superseded

  • monthly_pta_reports — JSON snapshot can't track per-line status.
  • em_enable_requests / em_enable_request_items — superseded by the request-tracking project's records.

Reused / extended

  • pta_accounts, project_pta_mapping — kept current by approval-time PTA sync.
  • external_modules_charges — monthly charge source (hub-synced); later extended with source + R2P2 traceability for the historical migration.
  • EM-records project (PID 16000) — fee fields + new auto_enable/requestable flags.
  • Request-tracking project — instruments: request survey (requester + person-lookup approver), approval survey (whole-request decision), repeating EM line (prefix, fee/auto-enable snapshots, line_status, Jira key, source = request/grandfathered/auto_detected).

7) Status Dictionaries

Request EM-line statuses

pending → approved → enabled | awaiting_super_user (→ enabled via reconciliation) | approval_error (retryable) · pending → rejected · enabled → deactivated

Billing line statuses

StatusMeaningNext behavior
pendingAwaiting finance resultAwait import / manual override
chargedFinance completed chargeClosed; no carry-forward
rejectedPTA charge failedNew line next month — same amount, attempt+1, project's current PTA
waivedCharge forgivenClosed; no carry-forward
holdFinance hold / no PTA mappingCarries forward like rejected

Run statuses

draft → exported → finalized. One run per month; draft regenerates in place, exported/finalized blocks regeneration.

Finance CSV (summary — the editable file)

One row per PTA: billing_run_id · billing_month · pta_number (re-import key) · pta_description · contact_name · project_count · line_count · new_amount · carried_amount · total_amount · status · finance_note. Detail file (read-only): line_id · pta_number · project_id · project_title · module_prefix · amount · attempt_number · carried_from_line_id · status.

9) Verification (local REDCap docker)

  1. Billing: seed PTAs/mappings/charges → generate run (unmapped → hold/Unmapped) → download both CSVs → edit summary (one PTA charged, one rejected + note) → import → verify fan-out, finalize, re-import blocked, duplicate-generate blocked.
  2. Carry-forward: next month's run recreates rejected/hold lines (attempt 2, current PTA after changing a mapping); charged/waived don't reappear.
  3. Ledger: totals match open lines; manual mark-paid (note) removes from ledger with audit fields.
  4. Requests: cart checkout → record + survey redirect → Alert email → PI approve → auto-enable verified in project / Jira line awaiting_super_user → PTA mapping updated; reject and approval_error retry paths.
  5. Deactivation: core page annotations + Disable (reason recorded); native out-of-band disable → reconciliation files acknowledgment; manual enable of Jira line → flipped to enabled; grandfather seeding counts.
  6. Security: logged-out hit of ajax/finance_report_action.php?action=list_pta returns 403.
